# FENIX Lab 1.1 — квантовые записи и восстановление

Рабочий исследовательский и учебный стенд по статье **Sergei Gontsarenko,
“Decoherence without facts: a one-knob model of where which-path records live”,
draft v1.4, 2 ноября 2026 года**.

**Три раздельных результата:** что видно у системы → что можно узнать из
окружения → какое состояние получается после коррекции.

Это симулятор конкретной модели. Не подключение к квантовому компьютеру,
не экспериментальные данные и не универсальное средство исправления шума.


**Английский по умолчанию, переключатель EN / RU в шапке.** При первом открытии
используется английский, даже если браузер русскоязычный. Язык можно сменить без
сброса параметров, расчётов и уже выполненных испытаний Монте-Карло. Выбор
запоминается, если браузер разрешает локальное хранилище. Ссылка с `?lang=en`
или `?lang=ru` имеет приоритет над сохранённым выбором.

В шапке теперь коротко объяснено, что рассчитывает стенд. Два примера сразу
открывают соответствующие опыты: «Разобраться в квантовом стирании» — учебный

## 01. Один свидетель

Режим реализует §§2 и 6 статьи. В интерфейсе S начинается в |+⟩, E — в
ρE = (I + ηX)/2. Между ними действует controlled-phase с фазой φ.

Можно менять η, φ, направление чтения, вероятность перепутать +/−, шум
фазовой коррекции и способ её калибровки. Есть семейство Eq. (9), оси Z, X,
Y, оптимальное направление чтения пути d и произвольная ось на сфере Блоха.

Показываются:

- видимость до чтения, вероятность угадать путь по зарегистрированному ответу,
  видимость и фиделити после настоящего суммирования исправленных матриц;
- интерференционные полосы, точка (K,V) и теоретическая граница;
- условные состояния, вероятности ответов, фазы коррекции, матрицы системы;
- количество классической информации выбранного чтения, отдельно от K.

**Четыре готовых опыта:**

1. **«Нет свидетелей пути»**: η = 0, φ = π, Z-чтение. До чтения V = 0,
   угадывание пути = 50%, после идеальной коррекции V = 1.
2. **«Узнать путь»**: η = 1, φ = π, чтение d. Путь угадывается идеально,
   но интерференция этим протоколом не восстанавливается.
3. **«Исправить фазу»**: η = 0.6, φ = π/2, Z-чтение. Контроль правильного
   знака операции: восстановлено именно |+⟩, а не просто сумма модулей.
4. **«Y ≠ Z»**: η = 0.6, φ = π, Y-чтение. K = 0, но V после коррекции = 0.6.

### Два способа калибровки

**Учесть ε:** истинные условные ветви сначала смешиваются по матрице ошибок
классического ответа, затем выбирается оптимальная фаза для каждого
зарегистрированного ответа.

**Как при ε = 0:** применяется фаза, рассчитанная для идеального прибора,
даже если метка была перепутана. Это полезно для сравнения калибровок.

**Измерить, но не исправлять:** все ветви складываются без обратной связи.
Просто чтение окружения, когда ответ игнорируется, не меняет состояние S.

## 02. Ошибки и восстановление

Здесь строго **φ = π**, N независимых свидетелей. Это не обобщение чётностной
коррекции на произвольную φ: при общей фазе одного бита чётности недостаточно.

Сравниваются:

| Способ | Что происходит |
|---|---|
| Без чтения | Дефазированный канал, обратной связи нет |
| Отдельное Z-чтение | N ответов, из них считается чётность |
| CNOT → одно чтение | N−1 CNOT переносят чётность на E1; читается E1 |
| Коллективная чётность | Отдельный протокол с собственной полной ошибкой q |
| Идеальный эталон | Восстановление без ошибок; несовершенства отключены |

Для входного |+⟩ при N = 100, ε = 1%, p_g = 0.1%, q = 2%, σ = 0:

| Способ | V | F |
|---|---:|---:|
| Отдельное чтение | 0.1326196 | 0.5663098 |
| CNOT → одно чтение | 0.8038031 | 0.9019015 |
| Коллективный протокол | 0.9600000 | 0.9800000 |

Здесь сравниваются **условные математические сценарии**, не измеренные
характеристики приборов. Коллективный протокол не считается «бесплатным»:
его q должно учитывать всю физическую реализацию.

Начальное состояние можно переключить на |+i⟩, |0⟩, наклонённое чистое или
смешанное. Это показывает, почему V не равна F: например, состояние |0⟩ может
сохраняться идеально при V = 0.

### Ошибки CNOT: важное ограничение

p_g — вероятность независимого **X-переворота целевого кубита** после каждого
идеального CNOT. Это не общая инфиделити двухкубитного вентиля и не
деполяризующий канал. Шум на управляющих кубитах, коррелированные ошибки,
утечки, T1/T2, длительность операций не моделируются.

При N > 1, ε < 1/2 и одинаковом конечном шуме коррекции цепочка выигрывает у
отдельных чтений тогда и только тогда, когда p_g < ε. Это следствие именно
выбранной модели ошибок. При ε = 1/2 оба варианта дают C = 0.

### Информация о пути — отдельный опыт

Блок с фрагментом k считает X-чтение CZ-записей. Он не утверждает, что та же
партия кубитов одновременно читается в X и используется для Z-коррекции.

χ_k — информация о пути. Для входа |+⟩ полная взаимная информация всего
идеального окружения равна 1 + χ_N. Дополнительный бит не является битом о пути.
Для иных входов эти показатели используются как **равновероятная калибровка**,
а не как фактическая взаимная информация такого входа.

### Монте-Карло

Кнопка запускает синтетические испытания ошибок. Заданный seed воспроизводит
тот же результат внутри данной реализации. Выводится средняя знаковая
X-квадратура и оценка её стандартной ошибки.

Python использует NumPy Generator, JavaScript — Mulberry32; одинаковый seed
между двумя языками не обещает одинаковую случайную последовательность.
Сравниваются распределения и теоретические средние. Шум финального
квантового измерительного детектора в этих испытаниях не добавлен.

## Экспорт и повторение опыта

**JSON** сохраняет обе конфигурации, численные результаты, матрицы,
допущения и текущие результаты самопроверок. **Загрузить** принимает этот
экспорт и пересчитывает результаты, а не доверяет сохранённым ответам.
В `examples/` есть готовые импортируемые сценарии. Импорт не меняет выбранный язык.
JSON и CSV сохраняют стабильные английские ключи; числовые значения не зависят
от языка. Старые конфигурации 1.0 поддерживаются.

**CSV** в первом режиме содержит скан интерференционных полос, во втором —
таблицу сравнения протоколов. Десятичный разделитель в CSV — точка;
разделитель колонок — запятая. Файл имеет UTF-8 BOM для удобства открытия.

## Python-ядро

Требуется Python 3.10+ и NumPy. Проверено на Python 3.13.5 / NumPy 2.3.5
(точные сведения текущего запуска сохранены в `results/verification_summary.json`).

```bash
python -m pip install -r requirements.txt
python fenix_core.py --mode single --eta 0 --basis z --epsilon 0 --out result.json
python fenix_core.py --mode many --n 100 --epsilon 0.01 --gate-error 0.001 --out compare.json
```

В CLI вероятности задаются от 0 до 1, в интерфейсе поля ошибок — в процентах.
Углы CLI `--phi-deg` / `--theta-deg` — градусы. В Python API — радианы.

```python
import math
from fenix_core import single_witness, recovery_comparison, RecoveryConfig, state

result = single_witness(
    eta=0.6,
    phi=math.pi / 2,
    basis="z",
    readout_error=0.01,
    correction="calibrated",
)
print(result["system"]["visibility"])
print(result["environment"]["p_guess_reported"])
print(result["corrected"]["rho"])

# Неизвестная фаза входа сохраняется: коррекция определяется каналом,
# а не аргументом входного состояния.
rho = state(theta=1.1, phase=0.7, bloch_radius=0.8)
comparison = recovery_comparison(
    RecoveryConfig(n=100, eta=0.6, readout_error=0.01,
                   gate_flip_error=0.001, collective_error=0.02),
    rho_in=rho,
)
```

`bloch_radius` в функции `state` — радиус Блоха, не Tr(ρ²).
Сам Tr(ρ²) возвращается в метриках как `purity`; для радиуса r это (1+r²)/2.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python verify.py
```

Команда запускает численные pytest-тесты. Если установлен Node.js, дополнительно
запускает 14 самопроверок JS, 147 сравнений двух реализаций и тесты локализации. Отчёт сохраняется
в `results/`. Отсутствие Node означает пропуск, а не успешную проверку JS.

Опционально для повторения браузерных тестов нужны Playwright и Chromium:

```bash
python -m pip install playwright
python -m playwright install chromium
python tests/browser_i18n.py
python tests/browser_smoke.py
```

Независимый матричный эталон для малых N находится в
`tests/reference_density.py`. Он строит полные состояния, применяет реальные
CNOT и шумовые каналы, перебирает ошибки чтения и складывает исправленные ветви.
Проверяется не только модуль когерентности, но и матрица целиком.

## Структура проекта

- `index.html` — готовый автономный интерфейс.
- `fenix_core.py`, `fenix_core.js` — расчётные ядра, независимые от интерфейса.
- `app.template.html`, `app_ui.js`, `build.py` — исходники и сборка интерфейса.
- `i18n.js`, `i18n/en.json`, `i18n/ru.json` — локальный перевод интерфейса без внешнего сервиса.
- `docs/MODEL_NOTES_EN.md` — английская версия математической спецификации.
- `tests/` — матричный эталон, Python, межъязыковые и браузерные проверки.
- `docs/MODEL_NOTES_RU.md` — формулы, конвенции, разделение статьи и расширений.
- `examples/` — импортируемые JSON и Python-пример.
- `results/` — сохранённые проверочные результаты и снимки интерфейса.

После изменения JS или шаблона выполните `python build.py`. Никакие
авторские PDF, скрипты из PDF и прежние рецензии этот проект не меняет.
